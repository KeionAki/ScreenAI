## 1. 系统概述

本系统是一个运行在 macOS 上的后台应用程序，通过用户自定义按键触发屏幕捕获，将捕获的屏幕图像发送至多模态大模型 API 进行题目识别与解答，分析结果通过局域网实时推送至 iPhone 端 PWA 应用显示。电脑端同时提供置顶滚动字幕窗口作为可选显示方式。

### 1.1 核心特性

| 特性 | 描述 |
|------|------|
| **按键触发捕获** | 用户自定义全局快捷键，按下即捕获当前屏幕图像 |
| **灵活捕获范围** | 支持全屏、指定窗口、指定区域、指定显示器 |
| **AI 题目解答** | 调用多模态大模型，从屏幕图像中识别题目并作答 |
| **局域网实时推送** | 通过 WebSocket 将分析结果实时推送到 iPhone |
| **验证码认证** | 6 位验证码 + 60 秒倒计时 + 连接确认 |
| **双端显示** | 电脑端滚动字幕窗口 + 手机端 PWA 实时消息流 |
| **CSV 历史记录** | 本地 CSV 文件保存分析历史，不保留截图 |
| **低资源占用** | 按需捕获，无定时轮询，内存/CPU 占用最小化 |

### 3.1 菜单栏图标模块（Menu Bar Extra）

macOS 没有 Windows 意义上的系统托盘，使用 `NSStatusItem` 在菜单栏创建图标。

**功能列表**：
- 显示当前运行状态（运行中/已停止）——通过图标颜色变化或小圆点指示
- 「启动捕获」/「停止捕获」切换选项
- 「显示验证码」——手动打开验证码窗口
- 「打开设置」
- 「查看历史记录」
- 「退出」

**技术实现**：
- `NSStatusBar.system.statusItem(withLength:)` 创建状态项
- 使用 `NSMenu` 构建下拉菜单
- 状态指示：运行中显示绿色圆点图标，停止显示灰色圆点图标

### 3.3 全局快捷键监听模块

**技术实现**：
- 使用 `NSEvent.addGlobalMonitorForEvents(matching: .keyDown)` 监听全局按键
- 使用 `CGEvent` 或 `Carbon RegisterEventHotKey` 实现更可靠的全局热键
- 推荐使用 `KeyboardShortcuts` 库（开源）或自行基于 Carbon API 封装

**推荐实现**：基于 Carbon `RegisterEventHotKey` 的封装，可靠性高，不受焦点影响。

**快捷键默认值**：`⌘⇧A`（Command + Shift + A）

**用户自定义**：设置面板中提供录制按钮，点击后捕获用户按下的组合键并保存。

**注意**：快捷键触发后需防止重复触发，设置防抖间隔（如 500ms 内不重复响应）。

### 3.4 屏幕捕获模块

**技术选型**：ScreenCaptureKit（macOS 12.3+）

#### 3.4.1 全屏捕获流程

```swift
import ScreenCaptureKit

// 1. 获取可用的屏幕内容
let shareableContent = try await SCShareableContent.excludingDesktopWindows(
    false, 
    onScreenWindowsOnly: true
)

// 2. 选择目标显示器
let display = shareableContent.displays.first { $0.displayID == targetDisplayID }

// 3. 创建过滤器
let filter = SCContentFilter(display: display, excludingWindows: [])

// 4. 创建捕获配置
let config = SCStreamConfiguration()
config.width = Int(display.width)
config.height = Int(display.height)
config.minimumFrameInterval = CMTime(value: 1, timescale: 60)
config.showsCursor = true  // 是否显示鼠标光标
config.captureResolution = .best

// 5. 捕获单帧
let image = try await SCScreenshotManager.captureImage(
    contentFilter: filter,
    configuration: config
)
```

#### 3.4.2 指定窗口捕获

- 在 `SCShareableContent.windows` 中按 `windowID` 匹配目标窗口
- 使用 `SCContentFilter(desktopIndependentWindow: window)`
- 需要用户在系统设置中授予「屏幕录制」权限
- 窗口关闭后，捕获会抛出错误，根据用户设置决定停止或回退

#### 3.4.3 指定区域捕获

- 使用 `SCContentFilter(display:excludingWindows:)` 获取整个显示器画面
- 然后在获得的 `CGImage` 上使用 `cropping(to:)` 裁剪出用户选择区域
- 区域坐标存储为 `CGRect`（相对于所选显示器的坐标系）

#### 3.4.4 指定显示器捕获

- 枚举 `SCShareableContent.displays`，显示每个显示器的名称和分辨率
- 用户选择具体显示器后，仅捕获该显示器画面
- 显示器断开时，捕获会失败，触发异常处理逻辑

#### 3.4.5 权限申请

- 首次使用前，通过 `SCShareableContent` 的调用自动触发系统权限弹窗
- 在设置面板中提供「检查屏幕录制权限」按钮
- 使用 `CGPreflightScreenCaptureAccess()` 检查权限状态

#### 3.4.6 图像格式转换

- `SCScreenshotManager` 返回 `CGImage`
- 转换为 JPEG 数据（质量 0.85）或 PNG 数据
- 转为 Base64 编码字符串用于 API 请求
- 在内存中进行，不落盘

### 3.5 AI 分析模块

#### 3.5.1 API 调用流程

```
屏幕截图(CGImage)
    ↓
图像压缩编码 (JPEG, 质量0.85)
    ↓
Base64 编码
    ↓
构建 API 请求 (multipart 或 JSON)
    ↓
发送 HTTP POST 请求
    ↓
接收 JSON 响应
    ↓
解析文本内容
    ↓
传递给结果分发模块
```

#### 3.5.2 请求格式（OpenAI 兼容格式示例）

```json
{
  "model": "gpt-4o",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "你是一个题目识别与解答助手..."
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "data:image/jpeg;base64,{base64_data}"
          }
        }
      ]
    }
  ],
  "max_tokens": 2048,
  "temperature": 0.3
}
```

#### 3.5.3 API 提供商适配层

使用协议抽象，支持多提供商：

```swift
protocol AIServiceProvider {
    func analyze(imageBase64: String, prompt: String) async throws -> String
    var providerName: String { get }
}

// 具体实现
class OpenAIProvider: AIServiceProvider { ... }
class AnthropicProvider: AIServiceProvider { ... }
class GoogleProvider: AIServiceProvider { ... }
class CustomProvider: AIServiceProvider { ... }  // 自定义 OpenAI 兼容端点
```

**各提供商请求格式差异**：

| 提供商 | API 端点 | 请求格式 | 特殊字段 |
|--------|----------|----------|----------|
| OpenAI | `https://api.openai.com/v1/chat/completions` | OpenAI 格式 | `Authorization: Bearer {key}` |
| Anthropic | `https://api.anthropic.com/v1/messages` | Anthropic 格式 | `x-api-key: {key}`, `anthropic-version` |
| Google | `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` | Gemini 格式 | `?key={api_key}` |
| 自定义 | 用户填写 | OpenAI 兼容格式 | 用户自定义 |

#### 3.5.4 错误处理

| 错误类型 | 处理方式 |
|----------|----------|
| API Key 无效 | 推送错误消息到手机，电脑端滚动字幕显示红色错误提示 |
| 请求超时 | 重试一次，再失败则推送超时错误 |
| 模型不存在 | 推送错误消息，提示检查模型名称 |
| 图片过大 | 自动降低 JPEG 质量或缩小分辨率后重试 |
| 网络不可用 | 推送网络错误，提示检查互联网连接 |
| 限流 (429) | 等待后重试（指数退避），最大 3 次 |

#### 3.5.5 并发控制

- 同一时间仅允许一个分析请求进行
- 分析期间快捷键触发被忽略（防抖 + 互斥锁）
- 用户可在设置面板看到「分析中...」状态

### 3.7 滚动字幕窗口模块

**技术实现**：SwiftUI 无边框透明窗口，`NSWindow.Level = .floating`（始终置顶）

#### 3.7.1 窗口特性

| 特性 | 实现方式 |
|------|----------|
| 始终置顶 | `window.level = .floating` |
| 鼠标拖动 | 设置 `isMovableByWindowBackground = true` |
| 无边框 | `window.styleMask = [.borderless, .nonactivatingPanel]` |
| 背景透明 | `window.isOpaque = false`，`window.backgroundColor = .clear` |
| 不抢焦点 | `window.canBecomeKey = false`（用户仍可与其它应用交互） |
| 跨桌面 | `window.collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]` |

#### 3.7.2 界面布局

```
│  [第3条历史结果 - 更小字号，静态显示]        │
```

### 3.8 本地 HTTP/WebSocket 服务器模块

**技术选型**：使用 SwiftNIO 或 Network.framework（macOS 原生）实现轻量 HTTP + WebSocket 服务器。

**推荐**：使用 `Network.framework` 的 `NWListener` 实现，或集成 `Vapor` / `Hummingbird`（但较轻量方案更好）。考虑到资源占用，推荐使用 **SwiftNIO** 或 **Network.framework** 自实现。

#### 3.8.1 HTTP 端点设计

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/` | 返回 PWA 入口 HTML 页面 |
| GET | `/manifest.json` | PWA 清单文件 |
| GET | `/icon.png` | PWA 图标 |
| GET | `/sw.js` | Service Worker 注册文件 |
| GET | `/api/status` | 获取服务器状态（是否有连接等） |
| POST | `/api/auth` | 验证码验证，成功后建立 WebSocket 连接 |
| GET | `/api/history` | 获取 CSV 历史记录（JSON 格式） |
| GET | `/api/history/export` | 导出全部历史记录 |
| GET | `/ws` | WebSocket 升级端点 |

#### 3.8.2 验证码认证流程

```
1. 用户在电脑端点击「显示验证码」
2. 电脑端生成 6 位随机数字验证码
3. 弹出置顶小窗口显示验证码 + 60秒倒计时环
4. 手机端访问 http://[Mac局域网IP]:8899/
5. 手机端显示验证码输入框
6. 用户输入验证码
7. 手机端 POST /api/auth { code: "123456" }
8. 服务器验证：
   - 验证码是否匹配
   - 验证码是否在有效期内
9. 验证成功：
   - 返回 { success: true, token: "临时会话token" }
   - 电脑端验证码窗口显示「已成功建立连接」→ 自动消失
   - 手机端跳转到实时消息流页面
10. 验证失败：
    - 返回 { success: false, error: "验证码错误或已过期" }
```

#### 3.8.3 验证码窗口设计

- 独立小型置顶窗口（约 200×150pt）
- 6 位验证码以大字显示
- 窗口外围有一圈圆形进度条，显示 60 秒剩余时间
- 进度条颜色随时间变化：绿色 → 橙色（<20s）→ 红色（<10s）
- 过期后自动刷新新验证码，进度条重置
- 连接成功后，窗口内显示绿色对勾 + 「已成功建立连接」，延迟 1.5 秒后自动消失
- 验证码使用 `Timer` 每 0.1 秒更新进度条

#### 3.8.4 WebSocket 消息推送

WebSocket 连接在验证成功后建立，用于实时推送分析结果。

**服务器 → 手机端消息类型**：

| type | 描述 |
|------|------|
| `analysis_result` | AI 分析结果 |
| `error` | 错误消息 |
| `status_change` | 状态变化（窗口关闭/显示器断开等） |
| `heartbeat` | 心跳包（每 15 秒） |

**WebSocket 连接管理**：
- 维护当前连接的客户端列表
- 仅允许验证通过的客户端连接
- 检测到连接断开后，更新连接状态
- 手机端断线重连时，需重新验证（token 有 24 小时有效期）

### 5.2 局域网发现（可选扩展）

当前版本用户手动在 iPhone 浏览器输入 `http://[Mac IP]:8899/`。未来可扩展使用 Bonjour 服务自动发现。

### 5.3 连接状态管理

```
状态机:
  idle (未连接)
    ↓ 验证成功
  connected (已连接)
    ↓ WebSocket 断开
  disconnected (已断开，等待重连)
    ↓ 重新验证或自动重连
  connected
```

- 电脑端菜单栏图标显示当前连接状态
- WebSocket 心跳每 15 秒一次，检测连接活性
- 心跳超时 45 秒未响应则视为断开
- 手机端断线后显示重连提示

### 5.4 消息保证

- WebSocket 基于 TCP，保证消息有序到达
- 不实现消息持久化队列（实时场景，断线期间消息不补发）
- 手机端可通过历史记录 API 获取断线期间的分析结果

## 7. 关键流程

### 7.1 应用启动流程

```
1. 用户点击应用图标启动
2. 初始化日志系统
3. 从 UserDefaults 加载所有设置
4. 从 Keychain 加载 API Key
5. 创建菜单栏图标

8. 检查屏幕录制权限
```

```
  ├─ 是 → 忽略
  └─ 否 → 继续
        ↓
[检查是否已有分析进行中？]
  ├─ 是 → 忽略，状态显示"分析中"
  └─ 否 → 继续
        ↓
[根据设置确定捕获范围]
  ├─ 全屏 → 获取主显示器画面
  ├─ 指定显示器 → 获取目标显示器画面
  ├─ 指定窗口 → 查找窗口是否存在
  │   ├─ 存在 → 捕获窗口

  │       └─ 如停止 → 推送状态变化消息到手机

[Base64 编码]
        ↓

  ├─ 成功 → 提取文本内容
  └─ 失败 → 按错误类型处理
        ↓
[结果分发]
  ├─ 写入 CSV 历史记录（同步执行）
  ├─ 滚动字幕窗口更新（异步，主线程）
  └─ WebSocket 推送到手机（异步）
        ↓
[释放内存中的图像数据]

[回到就绪状态]
```

## 8. 异常处理与降级策略

### 8.1 异常场景处理表

| 场景 | 检测方式 | 处理策略 |
|------|----------|----------|
| 屏幕录制权限被撤销 | 捕获前检查权限 | 推送权限错误，引导用户重新授权 |
| API Key 无效/过期 | API 返回 401 | 推送错误消息，提示检查 API Key |
| API 请求超时 | 超时定时器触发 | 重试 1 次，仍失败则推送超时错误 |
| API 限流 | 返回 429 | 指数退避重试（2s → 4s → 8s），最大 3 次 |
| 网络不可用 | 请求失败 | 推送网络错误消息 |
| 目标窗口关闭 | 捕获时窗口不存在 | 按用户设置处理（停止/回退全屏） |
| 目标显示器断开 | 捕获时显示器不可用 | 按用户设置处理（停止/回退全屏） |
| 手机端断连 | WebSocket 心跳超时 | 更新连接状态，菜单栏指示 |
| 磁盘空间不足 | CSV 写入失败 | 推送磁盘空间警告 |
| HTTP 端口被占用 | 服务器启动失败 | 推送端口错误，提示更改端口 |
| 系统休眠/唤醒 | 系统通知 | 唤醒后恢复监听，休眠前暂停 |

### 8.2 降级策略

| 降级场景 | 降级方案 |
|----------|----------|
| 图像过大导致 API 失败 | 自动降低 JPEG 质量（0.85 → 0.6 → 0.4）或缩小分辨率后重试 |
| 滚动字幕窗口无法显示 | 自动切换为仅手机端推送 |
| 手机端未连接 | 仅电脑端滚动字幕显示，CSV 仍正常记录 |
| AI 返回异常格式 | 原样输出 AI 返回内容，标记为「原始输出」 |
| CSV 写入失败 | 内存中缓存最近 10 条，尝试稍后重写 |

---

## 9. 资源优化方案

### 9.1 内存优化

- 截图的 `CGImage` 在处理完成后立即释放
- 使用 `autoreleasepool` 包裹图像处理代码
- 不缓存截图，处理完即弃
- CSV 写入使用追加模式，不加载整个文件到内存
- 滚动字幕窗口仅保留设置数量的文本，超出自动移除
- WebSocket 推送后立即释放消息数据

### 9.2 CPU 优化

- 按键触发而非定时轮询，空闲时 CPU 占用接近 0
- JPEG 编码使用硬件加速（ImageIO 自动支持）
- 滚动动画使用 `CADisplayLink` 或 `TimelineView`，仅在窗口可见时运行
- 验证码倒计时仅在窗口显示时运行 Timer
- 菜单栏图标静态更新，不频繁刷新

### 9.3 网络优化

- 仅在用户触发时发送 API 请求
- 图像使用 JPEG 压缩（质量 0.85）而非 PNG
- 截图在上传前进行最大尺寸限制（如宽度不超过 1920px）
- WebSocket 心跳间隔 15 秒，最小化网络流量
- 局域网通信不加密（用户确认），减少 TLS 开销

### 9.4 磁盘优化

- CSV 按日期分文件，单个文件不会无限增长
- 不保存截图原图，仅保存文本记录
- 历史记录可在设置中手动清理

## 10. 安全与隐私

### 10.1 安全措施

| 层级 | 措施 |
|------|------|
| API Key 存储 | macOS Keychain，非明文存储 |
| 手机连接认证 | 6 位验证码 + 60 秒有效期 + 一次性使用 |
| 局域网限制 | HTTP 服务器仅监听局域网接口，不暴露公网 |
| 会话管理 | 验证成功后颁发临时 token，24 小时有效 |
| 验证码安全 | 验证成功后立即失效，不可重用 |

### 10.2 隐私说明

- 截图在内存中处理，不落盘
- 截图通过 HTTPS 上传至用户配置的第三方 AI 服务
- 用户需自行确认 AI 服务提供商的隐私政策
- 本地 CSV 仅保存 AI 返回文本，不保存截图
- 局域网通信使用 HTTP/WebSocket 明文传输（用户已确认可接受）

### 10.3 权限要求

| 权限 | 用途 | 获取方式 |
|------|------|----------|
| 屏幕录制 | 屏幕/窗口捕获 | 系统弹窗，首次使用时触发 |
| 辅助功能（可选） | 全局快捷键监听 | 系统设置中手动授权 |
| 本地网络 | HTTP 服务器监听 | macOS 本地网络权限弹窗 |
